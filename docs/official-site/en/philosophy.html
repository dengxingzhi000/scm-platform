engineering principles

We build this way,
because boundaries
speak.

Architecture is not a set of technology preferences. It is a set of judgments that can be executed again and again. The eight below are the kind you can point to in code: each has a choice, a cost, and something we deliberately refuse to do.

I

Isolation before convenience

A tenant id is not optional. Missing means rejected.

The tenant is resolved at the request entrance, not “remembered” in business code. TenantFilter writes it into the thread context; TenantInterceptor appends an alias-qualified predicate to SELECT, UPDATE and DELETE at the MyBatis layer; AsyncTenantAutoConfiguration lets async threads inherit the same context. scm.tenant.required=true by default: a missing tenant raises TenantParseException. A service may disable SQL isolation, but disabling is an explicit action, not an omission.

The known limits are written here too: a JOIN only gets the predicate on its driving table, and a subquery in FROM is not filtered. Those queries need an explicit condition. Naming the limit is safer than hiding it inside the framework.

rejectedEvery service assembles tenant_id itself — one omission is an entire data boundary crossed.
chosenEntrance filter + SQL interceptor inject it once — business code does not have to “remember”.
costComplex JOINs still need human review; async work must use the tenant-aware executor.
II

Consistency has an edge

One transaction changes one aggregate.

Cross-database work is confined to service/query/ and service/command/; there are no cross-database joins in the codebase. Cross-service strong consistency uses Seata AT, and every database needs an undo_log. Order and inventory reservations use TCC with explicit confirm and cancel branches. Long flows use the Saga orchestration in scm-common/integration.

This is not because “eventual consistency is more advanced”. It is an admission of the cost of distributed transactions, placed where it can be seen: compensation actions, idempotent consumers, retryable messages.

rejectedA cross-database JOIN wrapped in one big transaction — unpredictable performance and no way to tell whose rollback failed.
chosenStrong consistency inside an aggregate; eventual consistency across services, each with a compensation.
costundo_log, TCC branches, idempotency tables and reconciliation are required.
III

Contract before implementation

An error response is part of the contract.

Responses use ApiResponse. Paging keeps the raw MyBatis-Plus echo (records, total, size, current) and the frontend normalizes it in contracts/page.ts, rather than inventing a second paging envelope on the server.

Exception handling is divided by bean: SecurityRestExceptionHandler owns authentication, authorization and validation; GlobalExceptionHandler owns everything else, including the catch-all. This keeps 404 as 404 and 405 as 405, and only messages from application-authored ServiceException/BusinessException may reach the client. Failures inside the filter chain go through SecurityErrorResponseWriter and never depend on advice.

rejectedOne catch-all for every exception — it shadows business exceptions and puts raw messages on the wire.
chosenExplicit ownership per bean; status codes resolve from exception type or annotation.
costNew exception types must be assigned to a handler; contract changes must reach the frontend.
IV

Hot and cold, separate paths

The hot path does not wait for a database.

Stock deduction, restock and flash-sale counters execute atomically in Redis Lua. Reservations last 900 seconds, convert to a real deduction after payment, and release on cancel or timeout. Alerts and daily snapshots have their own endpoints and never enter the order path. The order dashboard aggregates in PostgreSQL and binds timestamptz with create_time at time zone to avoid an eight-hour drift.

Redis is not the ledger. It carries promise and speed; PostgreSQL carries fact and reconciliation. The window between them is closed by compensation, idempotency and the reconciliation workbench.

rejectedWrite every deduction to PostgreSQL — hot-row locks and transaction overhead amplify order latency.
chosenIn-memory atomic operation + async ledger + reconciliation as the backstop.
costA short window exists between Redis and the ledger; expiry and cache invalidation need schedulers.
V

Rollback before release

Evolution is sustainable replacement, not a one-time rewrite.

Every service owns its Flyway version line: validate-on-migrate=true, out-of-order=false. New schema changes go into db/migration/V<n>__*.sql instead of appending to scripts/db/. Read-write separation is off unless a service sets spring.datasource.rw.enabled=true. Optional subsystems — UAA, mTLS, PKCE, two-level cache, data sync — are also off by default and require an explicit opt-in.

The frontend evolves the same way: shadcn/ui and Tailwind v4 are the target, while Ant Design 6 stays only on legacy pages. No new AntD pages, domain-by-domain migration, no big-bang rewrite.

rejectedOne migration line shared by all services — one failure blocks every release.
chosenOne version line per service plus opt-in capabilities.
costCross-service changes must be ordered explicitly; default-off means more configuration and verification.
VI

Deny by default

Denying by default is harder than allowing by default. It is also safer.

Audit writes only accept internal callers with an HMAC-SHA256 signature inside a 5-minute window, and the controller has no delete endpoint. Payment callbacks are rejected outright when keys are missing, rather than “accepted first and verified later”. A failed permission lookup returns 403 instead of allowing the request. WebAuthn and StepUpFilter re-check sensitive operations.

These choices make local integration harder: keys must be configured, tenant headers must be present, and scm-system must be reachable before permissions resolve. That friction is intentional, not unfinished work.

rejectedOpen the audit write endpoint to any logged-in user — that permits forging or erasing evidence.
chosenSigned writes only; unconfigured callbacks fail; failed permission lookups deny.
costKey distribution and rotation are operational duties; a misconfigured callback rejects legitimate notifications (by design).
VII

Observable is a requirement

A 500 without a trace id never happened.

A 5xx returns generic text and X-Request-ID; the full stack and trace id go to the log. Every service exposes /actuator/health; metrics flow into Prometheus and traces into SkyWalking. Error handling, audit and call chains are organized around the same request identifier, so debugging does not begin with guessing the timestamp.

rejectedReturn e.getMessage() to the browser — it leaks internals and cannot be aggregated.
chosenGeneric message + request id + structured logging.
costDebugging depends on logs and tracing; instrumentation and context propagation need upkeep.
VIII

Non-goals

Restraint is not conservatism. It is refusing to hide the cost.

Knowing what not to do is harder than knowing what to do. These are deliberate omissions; they keep the remaining choices focused.

  • No PaaSNot a general-purpose platform. It is for teams with supply chain domain knowledge, customization needs and operational ownership.
  • No numbersNo capacity or availability figures without a load test behind them. No decorative “millions of concurrent users” or “99.99%”.
  • No meshNo Service Mesh. At this scale, gateway + Nacos + Dubbo are enough; another control plane only adds failure surface.
  • No theaterNo capability that is not wired. No AI inference, no Canal sync, no ShardingSphere — none of them are in the running path.
  • No hidingNo “zero configuration” promise. Start order, keys, tenant headers and database initialization must be understood; docs lower the barrier, they do not replace knowledge.
Principles are not slogans.
They are the default answer to the next change.
