01

供应商与采购

解决的问题供应商资料散落在资质、联系人、账户与评价里，准入与风险没有统一口径。

SRM / Purchase
Admission

准入流程

草稿 → 提交 → 审核（通过／驳回）；只有准入通过且未列入黑名单的供应商才能启用，税号必须补全，每次变更写入变更日志。

Certificate

资质证照

按有效期自动判定有效、临期、过期或驳回；支持审核、到期查询与统计，资质到期数量进入供应商概览。

Risk

风险与合作状态

风险等级 1–3；合作状态 0–3 按合法路径流转；列入黑名单会同时停用并终止合作，移出黑名单不改变原准入状态。

Performance

绩效评分卡

评价按质量／交付／服务／价格加权计算总分并回写供应商绩效；评分卡按维度汇总并给出分级建议。

Profile

档案与主数据

画像聚合主数据、联系人、银行账户、资质、分类与最近变更；首个联系人／账户自动成为默认项，切换时自动取消旧默认。

Procurement

采购与结算

采购计划、询价、报价、比价、合同、采购单与收货；供应商对账单支持创建、确认与标记已付款。

02

库存与仓储

解决的问题可售库存必须在下单瞬间给出答案，而账面库存又必须能对上。

Inventory / WMS
Atomic

Redis Lua 原子扣减

扣减、回补与秒杀在 Redis 单线程内原子执行；热路径不查询 PostgreSQL，库存缓存保持短 TTL。

Reservation

预占与释放

预占默认 900 秒；支付成功确认预占并转为实扣；取消或超时释放；过期预占提供批量释放接口供定时任务调用。

Adjustment

调整与调拨

入库、出库、盘点调整与跨仓调拨按业务单号做幂等保护；重复请求不会重复记账。

Alert

水位告警

不足与缺货告警支持分页、统计、处理与全量扫描；库存恢复后自动解除对应告警。

Snapshot

每日快照

按日期、SKU 与仓库生成快照，支持水位趋势查询；同日重复生成会跳过已有记录。

Warehouse

仓储作业

入库／出库单、收货与发货、取消、库位与波次拣货；只有未收货／未发货的单据允许修改。

03

订单与履约

解决的问题订单状态一多，越权跳转和非法回退就会变成数据事故。

Order / Fulfillment
State machine

状态只能沿合法路径前进

PENDING_PAYMENT → PAID → PENDING_SHIP → SHIPPED → IN_TRANSIT → DELIVERED → COMPLETED；取消仅限待支付／已支付，终态不可再变。

Aggregate

校验在聚合内

OrdOrder.transitionTo() 调用 canTransitionTo() 与 validNextStatuses()；非法流转在领域层被拒绝，而不是靠控制器兜底。

Dashboard

订单看板

支持今日、近 7 天、近 30 天，对比上期或同比；按天／小时聚合收入与订单量，返回状态计数与积压量，趋势点带时间范围可下钻。

Contract

分页与校验

订单、订单中心与履约统一分页；写接口使用 @Valid；分页回显由前端契约层归一化。

Order center

电商订单中心

创建、支付、发货、送达、收货、取消；与供应链订单共用租户、权限与审计。

Fulfillment

履约链路

拣货 → 打包 → 发货（登记运单与承运商）→ 签收；取消记录原因；轨迹事件与最新轨迹单独查询。

04

物流与配送

解决的问题运单、轨迹、路线与配送范围各自为政时，履约结果无法解释。

TMS
Waybill

运单

创建、按订单或运单号查询、状态更新、取消与逻辑删除；取消记录原因与操作人。

Tracking

轨迹

轨迹节点上报；按运单或运单号查询、分页查询；履约侧可单独取最新一条轨迹。

Route

路线

骑手、配送日期、路线状态与增删改查；路线列表按配送日期分页。

Coverage

配送覆盖

按承运商维护配送区域，并校验省市区地址是否被覆盖。

Carrier

承运商

承运商与运单关联；运单状态与轨迹分开维护，避免把运输事实写进订单状态。

Boundary

职责边界

物流只负责运输事实；订单是否进入下一状态仍由订单聚合决定。

05

财务与资金

解决的问题业务单据、支付、对账与服务费之间，差额必须能落在一张表上。

Finance / Payment
Settlement

结算与发票

结算单与明细、发票分页（可按往来单位）、运费规则；财务数据与业务单据保持同一租户范围。

Reconciliation

对账工作台

创建时计算双方金额差异；按账期、状态与差异标记筛选；支持对账、确认与差异原因登记。

Service fee

平台服务费

账单创建、更新、删除、待支付列表与按账单登记实付；租户侧提供费率配置与计算任务。

Payment

支付单

创建、查询、分页、取消；同订单同渠道的重复请求返回已有待支付单，避免重复下单。

Callback

回调验签

支付宝 RSA2 验签并校验 app_id／seller_id；微信 v3 校验签名头、5 分钟时钟窗口并解密 resource；金额与渠道必须匹配本地支付单。

Refund

退款与幂等

退款单与退款服务；支付状态只允许待支付 → 已支付；已支付回调重复到达时按幂等处理。

06

平台治理

解决的问题权限、审批、审计与通知如果各写一套，租户边界会在每个服务里漏一次。

Tenant / Governance
Tenant

租户

生命周期、套餐、配额与平台费率；租户 ID 进入请求上下文、SQL 谓词与异步线程。

Access

权限

用户、角色、权限、部门与字典；URL 级权限校验；权限查询失败时直接拒绝，而不是放行。

Approval

审批

基于 Flowable BPMN：发起、通过、驳回、待办与流程状态查询；权限变更审批独立入口。

Audit

审计

@AuditLog 切面采集；写入必须携带内部 HMAC-SHA256 签名；不提供 HTTP 删除入口；高风险操作镜像到敏感操作表。

Notify

通知

模板、渠道偏好、通知审计；站内信分页、未读数、单条已读与全部已读。

Message

事件发布

事件发布服务（scm-message）：领域事件经 outbox 持久化后投递 Kafka，再由 analytics 等消费者消费；站内信由 scm-notify 负责，消息记录与通知审计分开维护。

07

文档与文件

解决的问题合同、单据与附件一旦有多个版本，“当前版本”和“谁改过”必须可回答。

Document / File
Template

模板版本

版本列表、创建新版本（版本号递增）、发布时归档旧版本并更新模板当前版本。

Variable

变量 Schema

保存与查询模板变量 Schema；变量定义必须是合法 JSON 数组，渲染前即可校验。

Render

渲染

按模板与变量数据渲染生成文档，文档初始状态为已生成。

Version

文档版本

文档分页、详情与手工登记；版本列表按版本号倒序，保留每一次渲染结果。

Trail

审计轨迹

生成、渲染、签署、归档等操作写入文档审计轨迹；签署与归档同时变更文档状态。

File

文件

元数据分页、30 分钟预签名访问地址、创建与删除；scm-file 使用 MinIO 客户端，兼容 S3／OSS。

08

数据与分析

解决的问题交易库不适合跨周期聚合，报表也不应该反压订单库。

OLAP
Layers

ODS → DWD → DWS → ADS

ClickHouse 内建立四层模型：ODS 保留原始 CDC 载荷，DWD 明细、DWS 汇总、ADS 看板；按 tenant_id 排序、按月分区。

Ingest

Kafka 接入

Kafka 消费者写入 ODS，保留 Kafka offset 与时间戳；ReplacingMergeTree 与 SummingMergeTree 按场景选择。

Query

声明式查询

指标、维度、数据集与字段元数据；按数据集与指标定义生成 SQL 并执行，按组织范围过滤。

Governance

治理

数据血缘登记与上下游查询、数据质量评估、物化结果管理。

Dashboard

看板

订单看板在 PostgreSQL 内聚合，避免把交易表整页搬到浏览器；跨周期分析走 ClickHouse。

Retention

保留策略

ODS 1 年、DWD 2 年、DWS／ADS 3 年；业务侧审计 2 年、登录 1 年、API 日志 90 天、通知 6 个月。

09

电商层

解决的问题面向消费者的会员、促销、商城与支付，要和供应链底座共用租户与权限。

Commerce
Member

会员

注册、档案、等级、积分增减与明细、收货地址与默认地址；重复注册返回已有会员。

Coupon

优惠券

模板发放时数据库原子扣减；使用前校验订单金额；核销幂等，同订单重复核销返回已使用结果。

Campaign

拼团与秒杀

发起与参团、成员查询；进行中的秒杀、库存校验与秒杀下单。

Mall

商城

卖家入驻、购物车增删改清空、商品评价发表与分页查询。

Search

搜索

商品搜索、相似商品、个性化推荐；单条与批量索引、全量重建、按 ID 移除。

Order center

订单中心

创建、支付、发货、送达、收货、取消；分页查询按订单号、用户与状态过滤。

10

控制台

解决的问题后端能力再多，没有一条连贯的操作路径就等于没有。

Next.js
Routes

50+ 路由

仪表盘、商品、订单、库存、仓储、物流、供应商、采购、财务、通知、租户、审批、审计、文档、文件与分析。

Stack

目标技术栈

Next.js 16.4 App Router、React 19、Tailwind v4、shadcn/ui；TanStack Query v5、TanStack Table v9。

Form

表单

React Hook Form + Zod；长表单使用 zodResolver 与统一 FormField。

Chart

图表

Recharts 负责 KPI，ECharts 负责复杂图形，G6 负责拓扑；全部按需加载，AG Grid 只通过 DataGrid 包装引入。

Contract

契约层

后端 DTO 放在 contracts/，feature 服务做字段映射；分页原始回显由 contracts/page.ts 归一化。

Migration

迁移状态

Ant Design 6 只保留在存量页面；不新增 AntD 页面，按域逐步迁移到 shadcn/ui。
