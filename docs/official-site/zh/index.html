SCM Platform 是一个多租户供应链管理平台：26 个可独立部署的后端服务，加一套 Next.js 控制台。 采购、库存、仓储、订单、履约、物流、财务、供应商 SRM、文档与数据分析，运行在同一套租户边界内。

01

隔离不是配置项，是请求的起点

租户标识在过滤器链的最前端被解析，写入线程上下文；MyBatis 拦截器再把谓词追加到每一条 SELECT、UPDATE、DELETE。 异步任务通过专用执行器继承租户上下文。默认缺省即拒绝；单个服务可以关闭 SQL 隔离，但边界不会悄悄消失。

链路 TenantFilterTenantContextHolderTenantInterceptorAsyncTenantAutoConfiguration
02

热路径只认内存里的原子操作

库存扣减、回补与秒杀走 Redis Lua，不在热路径查询 PostgreSQL。预占默认 900 秒，支付确认后转为实扣， 取消或超时自动释放；水位告警与每日快照走独立接口，不挤占下单链路。

脚本 deduct_stock.luaadd_stock.luaseckill.lua·900s
03

写入之前，先证明它可信

支付回调先验签再改单：支付宝走 RSA2，微信支付 v3 校验签名头并解密 resource，商户号、渠道与金额必须和本地支付单一致。 审计日志只接受内部服务用 HMAC-SHA256 签名的写入，并且没有 HTTP 删除入口。

02

能力地图

九个入口 · 功能页展开为十域
01 / SRM→

供应商与采购

准入、资质、风险与绩效散落时，供应商没有统一口径。

  • 准入、黑名单与合作状态
  • 资质有效期与到期提醒
  • 绩效评分卡回写档案
02 / WMS→

库存与仓储

可售承诺要即时，账面库存又要对得上。

  • Redis Lua 原子扣减
  • 预占、实扣与超时释放
  • 水位告警与每日快照
03 / ORDER→

订单与履约

状态一多，非法跳转就会变成数据事故。

  • 枚举状态机在聚合内执行
  • 订单看板按天／小时聚合
  • 拣货到签收的履约链路
04 / TMS→

物流与配送

运单、轨迹、路线与覆盖范围各自为政时，履约无法解释。

  • 运单与状态流转
  • 轨迹上报与查询
  • 承运商配送覆盖校验
05 / FINANCE→

财务与资金

业务单据、支付、对账与服务费之间，差额要落在一张表上。

  • 对账、确认与差异标记
  • 平台服务费账单与付款
  • 支付回调验签与退款
06 / GOVERNANCE→

平台治理

权限、审批、审计与通知不能各写一套。

  • 租户生命周期与配额
  • Flowable 审批流程
  • 签名写入的审计轨迹
07 / DOCUMENT→

文档与文件

多版本之后，“当前版本”和“谁改过”必须可回答。

  • 模板版本与变量 Schema
  • 文档版本与审计轨迹
  • 30 分钟预签名访问
08 / OLAP→

数据与分析

交易库不适合跨周期聚合，报表不能反压订单库。

  • ClickHouse ODS → ADS
  • Kafka 接入与原始载荷
  • 指标、血缘与质量评估
09 / COMMERCE→

电商与控制台

后端能力再多，没有连贯的操作路径等于没有。

  • 会员、促销、商城与订单中心
  • 50+ 控制台路由
  • 按需加载的图表与表格
03

近期加固

让边界可验证，而不是增加页面
SRM

供应商企业级档案

准入审核、资质有效期、风险等级、合作状态、绩效评分卡与变更日志统一到一份档案；资质到期可单独查询。

DOCUMENT

版本与轨迹

模板支持版本递增、发布归档与变量 Schema；文档支持版本列表、签署／归档状态变更，并把每次操作写入审计轨迹。

PAYMENT

回调验签

支付宝 RSA2 与微信支付 v3 验签、解密；商户号、渠道、金额三重校验；未配置密钥时直接拒绝，重复回调幂等。

ORDER

分页与状态机

订单中心与履约接口补齐分页和 @Valid；订单状态只能沿枚举定义的合法路径前进，终态不可再变。

FINANCE

服务费与对账

平台服务费账单支持待支付列表与付款登记；对账记录支持对账、确认与差异标记，差额留在同一条记录上。

INVENTORY

告警与快照

库存告警支持扫描、统计与处理；每日快照支持趋势查询，同日重复生成会跳过已存在的记录。
